# 第八章、结构化输出

LangChain的结构化输出（Structured Output） 指的是：

要求模型最终返回一个符合预定义结构的数据对象，例如固定字段的JSON、Pydantic 模型、TypedDict，而不再是无格式的自然语言文本。

这样做的价值主要有三点：

- 更容易被代码处理：下游系统可以直接读字段，而不是再从自然语言里做解析。
- 结果更稳定：减少“模型说法变了但意思差不多”导致的解析失败。
- 更适合工程化：适用于表单抽取、分类、路由、调用工具参数生成、工作流状态传递等场景。

目前LangChain 1.x 支持多种Schema与结构化输出方式：

- Pydantic（字段校验、描述、嵌套结构，功能最丰富）
- TypedDict（轻量类型约束）
- JSON Schema（与前后端/跨语言接口最通用）
- dataclass

只有 Pydantic 返回的是Schema类实例，其余三种方式返回的都是 字典 ；也只有 Pydantic 在类型不匹配时会抛出异常。

# 1：pydantic

它通过在运行时强制执行类型提示，确保数据的正确性和一致性，是生产场景首选 。

## 基本使用

需要满足的几个要素：

- 所有结构化输出的数据模型都必须继承 BaseModel
- 使用 类型提示 ，Pydantic 支持丰富的字段类型：str 、int、float、List[xxx]、Optional[xxx]等
- 使用 Field() 添加字段默认值和描述，帮助 LLM 理解字段含义

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from pydantic import BaseModel, Field
from scripts.regsetup import description

load_dotenv(verbose=True)

model = init_chat_model(
    model="gpt-4o-mini"
)

class Person(BaseModel):
    """
    人物信息
    """
    name: str=Field(description="姓名")
    age: int=Field(description="年龄")
    occupation: str=Field(description="职业")

structured_model = model.with_structured_output(Person)

result = structured_model.invoke("陆小凤是一名30岁的侦探")
print(result)
print(result.name)

# 运行结果
name='陆小凤' age=30 occupation='侦探'
陆小凤
```

## 高级特性

### 1、可选字段

问题：当某些消息中大模型未识别到填充字段怎么办？

```python
class Person(BaseModel):
    """
    人物信息
    """
    name: str=Field(description="姓名")
    age: int=Field(description="年龄")
    occupation: str=Field(description="职业")

structured_model = model.with_structured_output(Person)

result = structured_model.invoke("李寻欢是一名侠客")
print(result)

# 运行结果
name='李寻欢' age=30 occupation='侠客'
```

在 Pydantic 的 `BaseModel` 中将 `age` 属性默认定义为了**必填项（Without Default Value）**，但传递给大模型的文本 `"李寻欢是一名侠客"` 中完全没有提及年龄。

当大模型被强制要求按 Pydantic 结构输出，而输入文本又缺失特定字段时，模型为了不违反 Schema 约束，通常会产生以下行为：

- **幻觉/默认推测**：大模型（或底层 LangChain 解析逻辑）为了符合 `age: int` 的类型要求，“擅自”补充了一个合理的数字（比如 30）。
- **上下文残留（特定环境下）**：如果你是在同一个 Jupyter Notebook / Python 交互式环境中连续运行，且底层模型实例（`model`）开启了对话历史（Memory/Session），或者使用的 API 接口自带缓存机制，模型可能会受到上一次运行“陆小凤30岁”的上下文干扰。

**如何避免这种情况？**

如果你希望在输入信息缺失时，模型能够明确返回“未知”或不填，可以通过以下两种方式修改 `Person` 类：

方法一：将字段设为可选（Optional）

```python
from typing import Optional

class Person(BaseModel):
    """
    人物信息
    """
    name: str=Field(description="姓名")
    age: Optional[int]=Field(description="年龄")
    occupation: str=Field(description="职业")

structured_model = model.with_structured_output(Person)

result = structured_model.invoke("李寻欢是一名侠客")
print(result)

# 运行结果
name='李寻欢' age=None occupation='侠客'
```

方法二：在 Prompt/Field 描述中加以约束

```python
class Person(BaseModel):
    """
    人物信息
    """
    name: str=Field(description="姓名")
    age: int=Field(description="年龄。必须严格按照输入文本获取，如果没有提及就输出Unknow或0")
    occupation: str=Field(description="职业")

structured_model = model.with_structured_output(Person)

result = structured_model.invoke("李寻欢是一名侠客")
print(result)

# 运行结果
name='李寻欢' age=0 occupation='侠客'
```

如果嫌单独定义一个 Enum 类太麻烦，也可以直接导入 typing 中的 Literal ，直接在字段里把允许的值写死。

```python
from typing import Literal
model = init_chat_model(
    model="gpt-4o-mini"
```

```python
from pydantic import ValidationError
class User(BaseModel):
    name: str = Field(description="姓名", min_length=2, max_length=50)  # 限制姓名字符长度
    age: int = Field(description="年龄", le=120)   # 限制年龄最大值

try:
    user1 = User(name="tom", age="150")
    print(user1)
except ValidationError as e:
    print(e)
```
